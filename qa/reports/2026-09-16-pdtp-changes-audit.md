# Auditoría de cambios PDTP v+1

Fecha: 2026-09-16  
Alcance: diff de implementación PDTP frente a `HEAD` (ciclo v+1, cobertura, acreditación, tablero, planilla, móvil y migraciones).  
Método: lectura estática, comparación con el plan y revisión de evidencia de validación previa. No se modificó código ni se ejecutaron pruebas nuevas en esta auditoría.

## Resultado ejecutivo

El cambio no debe tratarse todavía como listo para liberar. La base de revisiones y ejecutores está presente y las validaciones deterministas previas pasaron, pero hay dos riesgos S1: la huella firmada cambió sin compatibilidad con programas ya firmados y el preflight anual aún interpreta v1/v2 como duplicados del mismo año. Además, la comparación contra la Base es parcial: puede mostrar/aplicar una decisión de actividad sin representar cambios de calendario, retiro o configuración por faena.

## Cobertura y evidencia

- Validación previa registrada: 3 suites PGlite, 191 pruebas; panel de cobertura 5 pruebas; `typecheck`, `lint`, `db:verify-migrations` y `git diff --check` pasaron.
- La cadena de migraciones fue verificada hasta `0300_nifty_namorita`; no se encontró edición manual del journal.
- En esta auditoría no se ejecutaron pruebas nuevas, conforme a la instrucción recibida.
- La sesión autenticada disponible no tenía autorización efectiva para PDTP: `/prevencion/pdtp` terminó en `/dashboard`. Las capturas de esa limitación están en `qa/reports/2026-09-16-pdtp-implementation/capturas/`. Por tanto, no hay UAT visual de v+1, cobertura, diffs, estados cero ni móvil para esta implementación.
- Falta una prueba focalizada que cree v1, active v2 y verifique un evento anterior al corte y otro posterior; la suite existente sólo cubre creación concurrente, clonación, cobertura y aplicación básica de una diferencia (`prevention-pdtp.test.ts:3730-3819`).

## Orden recomendado de remediación

1. Resolver compatibilidad de huellas y retirar el supuesto de firmas inexistentes (PDTP-A01).
2. Desactivar/replantear el preflight anual antes de migrar y hacerlo consciente de versiones (PDTP-A02/A07).
3. Rediseñar el modelo de diff/aplicación para que toda diferencia representada sea decidible y deje una huella coherente (PDTP-A03).
4. Corregir v1, cobertura y tablero (PDTP-A04–A06), luego completar pruebas temporales y UAT autenticada.
5. Aplicar las mejoras de estándares, navegación y clonación (PDTP-A08–A12).
