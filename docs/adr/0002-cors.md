# ADR 0002 — Sin CORS: política same-origin

**Estado:** Aceptado
**Fecha:** 2026-06-18
**Autores:** Auditoría (S-16)

---

## Contexto

Plataforma Chome es una aplicación Next.js (App Router) donde el
frontend y el backend (Server Actions + handlers `app/api/*`) se sirven desde
**el mismo origen**. No existe hoy ningún cliente externo (app móvil nativa,
SPA en otro dominio, integración B2B) que consuma la API desde otro origen.

## Decisión

**No se configura CORS.** No se emiten headers `Access-Control-Allow-Origin`
ni se habilita preflight para orígenes externos. El navegador, por política de
mismo-origen, ya impide que un sitio de terceros lea respuestas de la API.

Esto es además una propiedad de seguridad deseable: refuerza la mitigación CSRF
(ver [../security/CSRF.md](../security/CSRF.md)), porque ninguna página externa
puede leer datos autenticados de la aplicación.

## Consecuencias

- **Positivas:** menor superficie de ataque; CSRF mitigado por construcción;
  cero configuración que mantener.
- **A futuro:** si se agrega un cliente en otro origen (app móvil, portal de
  proveedores, integración con ERP), habrá que:
  1. Decidir el mecanismo de auth para ese cliente (API key/HMAC u OAuth, **no**
     cookies de sesión cross-site).
  2. Habilitar CORS de forma explícita y restringida (allowlist de orígenes,
     métodos y headers; nunca `*` con credenciales).
  3. Revisar la política CSRF para los nuevos endpoints.

## Alternativas descartadas

- **Habilitar CORS "por si acaso":** añade superficie de ataque sin un consumidor
  real. Se difiere hasta que exista la necesidad concreta.
