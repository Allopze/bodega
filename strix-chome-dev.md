AUTHORIZED SECURITY TESTING TARGET

Target:
http://localhost:3001

This is the development environment of the Servicios CHOME platform.

This environment is explicitly authorized for security testing.

You may perform aggressive application security testing against this target.

SCOPE

Only test:
http://localhost:3001
and endpoints, APIs, assets, WebSocket connections and routes belonging to this application.

Do not attack unrelated hosts or third-party services reached by the application.

TEST OBJECTIVE

Perform an exhaustive security assessment of the CHOME platform.

Explore the application deeply, including authenticated functionality when credentials are available.

Prioritize discovery and validation of:

1. Broken access control
2. IDOR / BOLA
3. Horizontal privilege escalation
4. Vertical privilege escalation
5. Authentication bypass
6. Session vulnerabilities
7. API authorization failures
8. Multi-user isolation failures
9. Faena isolation failures
10. Role and permission inconsistencies
11. SQL injection
12. NoSQL injection
13. Command injection
14. Server-side template injection
15. XSS
16. CSRF
17. SSRF
18. Path traversal
19. Arbitrary file upload
20. Local file inclusion
21. Remote file inclusion
22. Sensitive information disclosure
23. Exposed internal endpoints
24. Debug endpoints
25. Development-only functionality exposed to users
26. Mass assignment
27. Parameter tampering
28. Race conditions
29. Business logic vulnerabilities
30. Insecure direct API usage
31. Insecure WebSocket authorization
32. Weak password reset flows
33. Account enumeration
34. Missing rate limiting
35. Security header issues
36. CORS misconfiguration
37. Cookie and session misconfiguration
38. JWT vulnerabilities if JWT is used
39. File access authorization problems
40. Unauthorized modification or deletion of resources

APPLICATION-SPECIFIC TESTING

Pay special attention to CHOME's organizational authorization model.

Test whether users can access resources belonging to:

- another user
- another role
- another faena
- another department
- another organizational scope

Attempt identifier manipulation whenever resource IDs are present.

Examples:

/api/resource/123
/api/resource?id=123
/api/faena/123
/api/users/123

Attempt nearby, sequential, guessed and discovered identifiers.

Test GET, POST, PUT, PATCH and DELETE authorization independently.

Never assume that because a user cannot see something in the UI they cannot access it through the API.

AUTHENTICATION

If credentials are provided, authenticate normally through the application.

Preserve the authenticated session and explore all reachable application functionality.

Inspect browser traffic and API requests generated by the frontend.

Do not limit testing to routes linked directly from the UI.

Discover hidden and undocumented endpoints whenever possible.

DEVELOPMENT ENVIRONMENT

This is a disposable development environment.

You may:

- create test records
- modify test records
- delete test records
- upload test files
- test malformed inputs
- replay requests
- manipulate API parameters
- test authorization boundaries
- perform fuzzing with reasonable limits

Avoid denial-of-service attacks designed solely to exhaust CPU, RAM, disk or network resources.

Do not attack external third-party infrastructure.

VALIDATION

Do not report purely theoretical vulnerabilities.

Attempt to reproduce and validate findings.

For each confirmed vulnerability provide:

- Severity
- Vulnerability type
- Affected URL
- Affected API endpoint
- Required privileges
- Exact reproduction steps
- HTTP request where applicable
- Evidence
- Security impact
- Remediation recommendation

Prefer confirmed findings over speculative findings.
